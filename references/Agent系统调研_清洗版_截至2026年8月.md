### 1.2 三者的差异（可控性/成本/延迟）——🔶教材提炼表

> 说明：以下为基于官方文章定性表述 + 行业资料的归纳表，**非官方原文引文**。官方原文只做了定性对比（"Agent 常常比单次调用更贵、更慢"）。

| 维度 | 单次 LLM 调用 | Workflow（预编排） | Agent（自主循环） |
| :--- | :--- | :--- | :--- |
| 可控性 | 最高（单步、可预测） | 高（流程固定，决策点可审查） | 低（模型自主决策，路径不可穷举） |

| 延迟 | 最低 | 中（串行步骤叠加） | 最高（多轮往返 + 工具执行） |
| 失败模式 | 单点幻觉/格式错误 | 步骤固定，失败点可定位 | 级联失败、循环空转、越权动作 |

## 2. Agentic 设计模式：六种模式

### 2.1 六种模式定义与适用条件（官方文章）

| 模式 | 定义 | 适用 | 不适用 | 可信度 |
| :--- | :--- | :--- | :--- | :--- |
| Prompt Chaining（提示链） | 任务拆成固定步骤序列，前一步输出作为后一步输入 | 流程固定、可分解为多个简单步骤；希望每一步可调试/可检查 | 步骤间需要动态分支或反馈 | ✅ 官方文章 |
| Routing（路由） | 分类输入并导向专门的后续任务（不同 prompt/工具/子流程） | 存在可清晰区分的类别，分类可被准确完成（LLM 或传统分类器） | 类别边界模糊、分类本身不可靠 | ✅ 官方文章 |
| Parallelization（并行化） | 并行执行多个独立子任务（或对同一任务取多个视角后聚合） | 子任务独立、可并行；需要多样答案投票/分段处理 | 子任务间有强依赖 | ✅ 官方文章 |
| Orchestrator-Workers（编排者-工人） | 中央 orchestrator 动态拆解任务、委派 workers、汇总结果 | 子任务数量/类型动态变化、无法预写死流程 | 子任务固定且少——直接写流程更简单 | ✅ 官方文章 |
| Evaluator-Optimizer（评估-优化） | 生成器产出 → 评估器评判 → 不达标回炉（循环） | 有明确可判定的质量标准、迭代能明显改善结果 | 评判标准模糊、单轮生成已够好 | ✅ 官方文章 |
| 自主 Agent（Autonomous Agent） | 模型自主规划、调用工具、观察结果、循环直至完成 | 任务无法预写步骤、需要大量工具与环境交互 | 有简单固定流程可替代时 | ✅ 官方文章 |

- ✅ 镜像文本（便于核对小节原文）：[machinedge/building-effective-agents](https://github.com/machinedge/building-effective-agents/blob/main/building-effective-agents.md)

### 2.2 Routing 的"三路分流"设计（Router 分级）——🔶教材提炼

> 用户方口径："low→quick / high→deep / uncertain→escalate"（低价值→快路径；高价值→深度路径；不确定→升级/转人工）。该三路分流**不是官方原文的固定表述**，而是基于以下公开资料归纳的设计骨架：

| 公开资料 | 内容 | 可信度 |
| :--- | :--- | :--- |
| 官方 Routing 模式 | 分类输入后导向专门 prompt/工具；文章示例为客服路由（general→技术/计费/投诉等不同 prompt） | ✅ [Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents) |
| mcp-agent Router 模式 | Router 将请求分类到子 agent/工具；含 Intent Classifier（意图分类器）模式 | ✅ [docs.mcp-agent.com/router](https://docs.mcp-agent.com/mcp-agent-sdk/effective-patterns/router)；✅ [intent-classifier](https://docs.mcp-agent.com/mcp-agent-sdk/effective-patterns/intent-classifier) |
| OpenClaw Model Router | 开源 agent OpenClaw 新增"按层级自动选择模型"的路由器（Model Router，tier-based model selection）——即按任务复杂度/价值选择快模型或强模型 | ✅ [openclaw/openclaw PR #54562](https://github.com/openclaw/openclaw/pull/54562)（2026） |
| 升级（escalate）语义 | "不确定→转人工"在官方与业界 HITL 资料中普遍出现（见第 3、7 节事故与 HITL 资料） | ✅/⚠️ 见第 3 节来源 |

> 归纳：三路分流可表述为——**低风险/简单（low）→ 快路径（quick，小模型或轻量 prompt）；高价值/复杂（high）→ 深度路径（deep，强模型/多步流程）；置信度不足或超权限（uncertain）→ 升级（escalate，转人工或降级只读）**。🔶教材提炼，落地前建议对照 mcp-agent 与 OpenClaw 的实现文档。

## 3. 假阳性（False Positive）vs 假阴性（False Negative）在自动化边界中的应用

### 3.1 概念与在 Agent 中的映射

| 概念 | 在 Agent 自动化中的含义 | 代价 |
| :--- | :--- | :--- |
| 假阳性 FP | 不该打断时打断：审批门控误拦/频繁打断人类（如把正常操作判为危险） | 人类信任流失、效率下降、"狼来了"效应（用户开始机械点同意） |
| 假阴性 FN | 该拦时没拦：漏放危险动作（越权操作、破坏性命令、对外发布） | 真实事故、数据损失、法律/声誉风险 |

### 3.2 公开证据（FP 与 FN 两端的实测）

| 证据 | 内容 | 可信度 |
