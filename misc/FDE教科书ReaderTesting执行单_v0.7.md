# FDE 教科书 Reader Testing 执行单（G-4）

> **用途：** 发布前用"无上下文读者"检验《人工智能工程师（高级）FDE 认证培训·教科书》能否被三类目标读者独立读懂。
> **对应：** 整改操作手册 G-4 与发布 Gate（G-5）条件。
> **原理：** 编写者自带上下文，容易"以为读者看得懂"；无上下文读者答出冲突答案 = 正文有歧义，须反查修订。
> **配套：** 结果登记到 `misc/FDE教科书事实核验台账_v0.7.md`（G-4 行）。

---

## 一、三类目标读者与筛选标准

> 每类至少 1 人，**建议每类 2 人共 6 人**；三类都做齐才满足 G-4。

### 读者 A · Echo 背景（业务 / 产品 / 咨询侧）

| 维度 | 标准 |
|---|---|
| 画像 | 面向客户做需求、价值、方案的人：业务分析师、产品经理、售前/解决方案顾问、咨询顾问、To B/To G 项目负责人 |
| 技能基线 | 能读懂业务材料与数据口径；**不要求写代码**；日常不与 LLM 工程细节打交道 |
| 硬性条件 | ① 未参与本书编写与评审（无上下文）；② 有至少 1 个 To B / To G 交付或需求侧项目经验；③ 愿意投入约 2–2.5 小时 |
| 代表对象 | 教科书目标读者中"乙方 Echo"与"甲方内部需求/业务团队" |

### 读者 B · Delta 背景（技术 / 工程侧）

| 维度 | 标准 |
|---|---|
| 画像 | 动手实现的人：软件工程师、AI 应用工程师、使用过 AI Coding 工具（opencode/Cursor/Claude Code 等）的开发者 |
| 技能基线 | 会写代码、懂 API 调用与测试；**不需要**懂 RAG/LangGraph 细节（本书会教） |
| 硬性条件 | ① 未参与本书编写与评审；② 有实际软件交付经验（≥1 个项目）；③ 愿意投入约 2–2.5 小时 |
| 代表对象 | 教科书目标读者中"乙方 Delta"与"甲方内部交付/技术团队" |

### 读者 C · 培训组织者 / 讲师

| 维度 | 标准 |
|---|---|
| 画像 | 负责开班、排课、授课、评分的人：培训机构讲师、企业内训师、带教负责人 |
| 技能基线 | 懂教学设计（目标→活动→评估）；**不需要**精通本书技术细节；重点看"能不能教、怎么排课、怎么评分" |
| 硬性条件 | ① 未参与本书编写（可参与过使用，如带过往期课）；② 有授课或培训组织经验；③ 愿意投入约 2–2.5 小时 |
| 代表对象 | 教科书目标读者中"用这本书开课的一方" |

### 共同排除条件（违反任一条，结果作废）

- ❌ 参与过本书编写、逐章评审、或已通读全稿的人（视角已被污染）；
- ❌ 与编写者讨论过本书内容再作答的人（需独立完成）；
- ❌ 只浏览目录、不读正文就答题的人（答案不可信）。

## 三、答题表（读者填写，独立完成）

**请在阅读后回答以下 7 个问题，每题 2–5 句；回答不出来的题写"没找到答案"，并注明卡在哪一章/哪一节。**

1. **这本书的能力主线是什么？**（用一句话说清"学员学完带走什么"）

2. **我（按我的角色）应该按什么路径学习这本书？**（先读什么、后读什么、哪些必做）

3. **第 6 章的产出如何进入第 8/10/12 章？**（实操一的成果被后续实操怎么用？）

4. **第 14 章和第 15 章，学员需要"读"还是需要"做"？是否计分？**

5. **"教学模拟数据"与"真实客户数据"的处理边界是什么？**（什么能上公网 API、什么不能、为什么）

6. **如何判断一个场景该"Go / Conditional Go / Continue Pilot / No-Go"？**（判断依据来自哪里？）

7. **哪些内容是"教材提炼/教学假设"，哪些是"厂商官方事实"？**（各举 1–2 个例子，说明怎么区分的）

**附加题（可跳过）：** 阅读过程中最困惑/最想吐槽的一处（章节 + 问题），以及最想夸的一处。

## 四、预期答案要点（**组织者判卷用，不随答题表发给读者**）

| 题 | 预期要点（与当前正文一致） |
|---|---|
| 1 主线 | Echo 判断力 × Delta 施工力；卖人力→卖能力；西岭单案例贯穿；五个实操"总—分—总"闭环（第 6【总】→8/10/12【分】→16【总】） |
| 2 路径 | 导读"先修与预计学时"表即路径：认知打底（1–5）→ Echo 实操一（6）→ Delta 实操二三四（8/10/12，配 7/9/11 方法）→ 私有化与生产化（13/14）→ 价值与收口（15/16）；第 4 章角色练习定 Echo/Delta 倾向 |
| 3 Ch6→8/10/12 | 《解决方案框架》（每场景八字段，5.8.3/6.4.5）是施工任务书：选型、验收口径、数据边界由实操一定，第 8/10/12 章照着施工；默认阈值须标"教学初始值" |
| 4 Ch14/15 | **必做贯穿任务 + 知识支持**（导读与两章章首"本章属性"）：不是编号实操（不新增实操六/七），但要产出证据并计分——Ch14 产工程接管证据、Ch15 产价值与回注证据，供第 16 章综合评审 |
| 5 数据边界 | 教学模拟数据（完全虚构、脱敏、无真实个人信息）可在课堂批准环境用公网 API；真实客户数据须按分类分级/法规/合同在批准安全域内处理，不得"先入公网再补救"；"出域"分六类（7.4），"数据不出域"是本案例红线而非普遍法定义务 |
| 6 决策 | 依据第 14 章工程证据（八项生产准入）+ 第 15 章业务证据（价值/采用/回注）逐场景判断；决策单含依据、未关闭风险、责任人、下一 Gate；允许 Continue Pilot 与 No-Go（16.4.4） |
| 7 教材 vs 厂商 | 教材提炼/口径/教学假设有显式标注（如"教材提炼""教材口径""教学假设""教材解释假说"）；厂商事实带官方链接（SEC 财报、Anthropic/LangGraph 官方文档、厂商模型卡）；无来源的量化断言被降级或删除 |

## 五、冲突判定与修订动作

| 情况 | 处理 |
|---|---|
| 三类读者答案**一致且正确** | 该题通过 |
| 某类读者**答错/答不出** | 反查对应章节：是没写清、位置不对、还是表述歧义 → 修订该处并登记 |
| 两类以上读者答案**互相冲突**（如：A 说 Ch14 只读、B 说要做） | 高优先级：按第 3、4 题正文口径统一，并回到对应章节（导读结构段、Ch14/15 章首）修订 |
| 读者**普遍困惑**同一处 | 即使"不算错"，也视为可读性问题 → 简化或补一句过渡 |

修订后：更新导读修订记录 + `misc/FDE教科书整改问题台账_v0.7.md`；全部通过后，在事实核验台账 G-4 行登记"完成 + 结论"。
