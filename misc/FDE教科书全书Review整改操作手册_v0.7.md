> **适用范围：** `textbook/00_导读与体例说明.md`、第 01–16 章、`labs/`、`resources/`、根目录 `AGENTS.md`。

> **本轮目标：** 在不破坏“西岭单案例贯穿”和“五实操总—分—总”结构的前提下，完成能力闭环校正、事实校正、配套资源补齐和格式统一，使全书达到可读、可教、可学、可测、可执行、可维护的交付标准。

## 1. 本轮修订原则

### 1.1 必须保留的全书主线

全书继续沿用以下主线，不另起一套概念体系：

```text
FDE 认知
→ Echo 定义问题、价值与成功标准
→ Delta 分层施工并形成工程证据
→ Delta 完成生产落地与客户接管
→ Echo 完成价值落地与组织采纳
→ Echo + Delta 综合证据并作下一阶段决策
→ 能力回注
```

必须保留：

- “卖人力 → 卖能力”主线；
- Discovery → Prototype → Build → Scale 四阶段；
- 能力回注四步法：识别 → 抽象 → 集成 → 验证；
- 西岭市民服务平台单案例；
- 五实操总—分—总：第 6 章【总】→第 8/10/12 章【分】→第 16 章【总】；
- 实操四B作为无编号高级桥梁；
- Go / Conditional Go / Continue Pilot / No-Go 四类决策；
- 四条交付红线，但须区分“教材项目红线”与“普遍法律义务”。

### 1.2 双角色裁定

本课程只设置两种学员角色：

| 角色 | 核心能力 | 主责 |
|---|---|---|
| Echo | 判断力 | 需求、价值、采用、业务边界、成功标准、业务回注 |
| Delta | 施工力 | 实现、验证、生产化、接管、工程边界、工程回注 |

统一处理规则：

1. `Engineering` 不再作为第三条课程角色或认证路径。
2. 基础设施、安全、网络、运维、客户 IT 等改称“客户协作方”“平台/基础设施保障方”或“相关专业团队”。
3. 不要求学员认领第三战位，不设计第三角色画像、第三角色练习或第三角色评分。
4. 可说明真实交付需要多个专业团队协作，但课程能力模型始终是 Echo + Delta。
5. “双栖型”只能表示一个人可兼具两种能力，不得成为第三角色。

### 1.3 正文与实验手册分工

- 教科书正文：解释为什么、判断框架、角色分工、边界、反模式、验收思想。
- 实验手册：安装、环境、逐步操作、数据、提示词、命令、参考答案、排障。
- 资源包：模板、锁定依赖、认证量规、陌生案例、评分脚本、快速参考。
- 正文不得保留“待环境复核”“后续补齐”“随资源轮次补齐”等内部过程状态。

### 1.4 事实与信源原则

事实性内容按以下顺序取证：

1. 法律法规、政府和监管机构原文；
2. 厂商官方文档、官方模型卡、官方定价页、官方招聘页、官方财报；
3. 论文原文、项目官方仓库和正式技术规范；
4. 高质量第三方仅作补充，不用于单独证明型号、参数、许可证、价格或官方组织体系。

若找不到一手来源：

- 删除具名断言；或
- 改为通用描述；或
- 明确标注“教材提炼”“教学假设”“经验示意”；
- 不得用“落地前请复核”代替本轮编辑核验。

### 1.5 图表修改边界

- 不借机修改无关 Mermaid 图的方向、配色或节点文字。
- 只有当本操作手册明确要求修正图中知识错误时，才修改对应图。
- 超过 4 个节点继续使用垂直布局。
- 每幅 Mermaid 必须保留图题。

## 2. 团队分工建议

| 工作组 | 主要职责 | 不得单独决定的事项 |
|---|---|---|
| 总编/架构组 | 主线、角色、章节属性、先修关系、跨章口径 | 技术事实与法规结论 |

- 上公有云；
- 向第三方处理者提供；
- 跨境；
- 出组织批准安全域。

3. 真实客户数据：必须在Discovery中按数据分类分级、法律法规、行业监管、合同、组织制度和审批结果确定处理边界。
