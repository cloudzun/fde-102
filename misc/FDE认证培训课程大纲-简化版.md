# 人工智能工程师（高级）FDE 认证培训 · 课程大纲

> **核心链路：** FDE 认知筑基 → Echo 业务策略 → Delta 快速施工 → 团队交付闭环
> **教学形式：** 2 天 / 12 学时（每天 6 小时）· 理论:实战 ≈ 4:6
> **贯穿场景：** 西岭市民服务平台 · AI 智能化项目（统一贯穿案例）
> **工具链：** 大模型 + 代码智能体 + 专业技能集合
> **认证出口：** 工信部教育与考试中心 · 人工智能工程师（高级）证书

---

## 一、培训背景

当前大模型、AI Agent 等生成式 AI 技术已全面进入企业规模化落地阶段，但 AI 落地断层普遍存在：需求说不清、Demo 出不来、系统上不了生产，大量项目停留在 PoC 阶段难以量产，无法创造持续业务价值。市场对兼具"能听懂业务、能动手实现、能交付落地"能力的复合型 FDE（Forward Deployed Engineer，前沿部署工程师）人才需求激增，而传统开发、运维、数据、算法人员技能割裂，难以独立完成端到端 AI 交付。

本课程正是为填补这一人才缺口而设计——以 Palantir 开创的 FDE 交付模式为方法论底座，用特种作战单元的 **Echo（业务策略）** 与 **Delta（技术执行）** 双角色主线，帮助学员建立从需求挖掘、方案设计到快速原型、交付落地的完整能力闭环。

---

## 二、课程定位

本课程围绕 FDE（Forward Deployed Engineer，前沿部署工程师）的完整交付能力设计，核心特色：

1. **角色主线贯穿**：用 Palantir 特种作战单元的 **Echo（业务策略工程师）→ Delta（技术执行工程师）** 角色分工作为两天主线，让学员带着"角色身份"完成交付闭环。
2. **Day 1 侧重 Echo**：讲透 FDE 的概念、流程与最佳实践后，重心放在"听懂真需求、出方案框架"——这是 FDE 的翻译与策略能力。
3. **Day 2 侧重 Delta**：用代码智能体（code agent）快速施工 Demo / PoC，重心放在"手上沾泥、快速出原型"——这是 FDE 的技术执行能力。
4. **一个真实场景贯穿**：以"西岭市民服务平台"统一案例贯穿两天，Day 1 拆解需求出的"施工图"，就是 Day 2 Delta 施工的"任务书"，两天串成完整项目交付线。

---

## 三、课程目标

完成培训后，学员能够：

1. 准确描述 FDE 的定义与三层含义（岗位 / 团队 / 方法论），理解"从卖人力到卖能力"的本质，区分 FDE 与售前、实施、外包、咨询等相邻角色；
2. 理解传统项目制"死亡螺旋"的结构性困境与四种交付模式（SaaS / 咨询 / 外包 / FDE+平台）的对比逻辑，用能力回注飞轮与经验曲线解释 FDE 为什么"越做越省"，并用 Palantir 财务证据（毛利率 50%→82%、NRR、单客户收入）佐证；
3. 描述 AI 项目全生命周期四阶段（Discovery → Prototype → Build → Scale）的核心任务、交付物与 Gate 检查清单，理解"能力回注"四步法（识别→抽象→集成→验证）与"碎石路→铺装公路""五次部署法则"；
4. 理解 Echo 与 Delta 的分工协作：Echo 挖痛点、出策略、定义问题边界、驱动落地；Delta 写代码、搭原型、部署上线，并理解"分工解耦 × 战斗力整合"的作战单元哲学；
5. 扮演 **Echo**（业务策略工程师 / Deployment Strategist）：用 Discovery 期 SOP（干系人地图 / 痛点诊断 / 数据资产盘点 / 快赢场景筛选）穿透模糊需求，定义"最值得解决的真问题"，把大需求拆解为可施工的子场景并完成技术路线选型，产出解决方案框架；
6. 扮演 **Delta**：用 Vibe Coding 工作法（Think → Plan → Build → Review → Test → Ship → Reflect）驱动代码智能体从零搭建可运行的 RAG 问答系统与业务 Agent；
7. 理解 RAG 与 Agent 的适用边界与架构决策，掌握"答案可追溯"的交付标准与"自动化边界"判断力；
8. 整合 Echo 方案框架 + Delta 两个施工成果，完成 ROI 量化、能力回注思考与面向决策层的汇报。

---

## 四、培训收益

完成培训后，学员将带走以下可落地能力：

1. **掌握 FDE 交付方法论**：理解"从卖人力到卖能力"的本质，能运用四阶段交付流程（Discovery→Prototype→Build→Scale）与能力回注四步法推进真实 AI 项目；
2. **具备 Echo 业务策略能力**：用 Discovery 期 SOP（干系人地图 / 痛点诊断 / 数据盘点 / 快赢筛选）穿透模糊需求，把大需求拆解为可施工子场景，完成技术路线选型，产出解决方案框架；
3. **具备 Delta 技术执行能力**：用 Vibe Coding 工作法驱动代码智能体，从零搭建可运行的 RAG 问答系统与业务 Agent，掌握"先写规格再动手"的工程纪律；
4. **建立交付质量标准**：掌握"答案必须可追溯"的 RAG 交付标准与"自动化边界"判断力，能设计带工具调用、人工回环的智能业务流程；
5. **完成团队交付闭环**：能整合方案框架与 Demo 成果，完成 ROI 量化、能力回注思考，面向决策层清晰汇报项目价值；
6. **获得权威认证**：通过工信部教育与考试中心《人工智能工程师（高级）》认证考试，实现"学技能 + 拿证书"一站式提升。

## 八、课程内容详解

> 本课程内容按四篇组织，每篇对应一个半天，章内小节为知识单元。

### 第一篇：FDE 认知筑基（Day 1 上午）

**第 1 章 FDE 是什么**

- 1.1 定义与起源：FDE 由 Palantir 首创，驻扎客户现场的全栈工程师，核心箴言"FDEs are the glue between our products and our customers"
- 1.2 三层含义：岗位（角色）/ 团队（组织模式）/ 方法论（交付范式）；类比 DevOps
- 1.3 三重角色融合：全栈工程师 × 业务顾问 × 产品经理（"三位一体"，最短闭环）
- 1.4 FDE ≠ 外包 ≠ 咨询：核心分野"从卖人力到卖能力"；判断标准——公司能力是否增长
- 1.5 AI 时代的 FDE 复兴：大模型落地五大鸿沟（模型≠产品 / 数据合规 / 微调工程 / 系统集成 / 搁板软件）

**第 2 章 为什么需要 FDE**

- 2.1 死亡螺旋：传统项目制"局部理性、全局自杀"的结构性困境，自我强化
- 2.2 四种交付模式对比：SaaS / 咨询 / 外包 / FDE+平台（"既要适配又要复用"）
- 2.3 经验曲线与飞轮：Cₙ = C₁ × n⁻ᵅ；能力回注飞轮三阶段（静止→加速→飞轮期）
- 2.4 承接逻辑反转：启动期"广撒种赌通用性" vs 成熟期"杠杆逻辑 + 负向筛选"
- 2.5 Palantir 财务铁证：毛利率 50%→82.4%、净利率转正、NRR 118%
- 2.6 FDE 退化警示：销售/交付压力侵蚀回注，自检"平台是否增长"

**第 3 章 流程与最佳实践**

- 3.1 四阶段方法论：Discovery → Prototype → Build → Scale（先找对问题→快速证明→做实做稳→放大复制）
- 3.2 能力回注四步法：识别 → 抽象 → 集成 → 验证
- 3.3 迭代哲学：碎石路 → 铺装公路（拒绝过早标准化，避免搁板软件）
- 3.4 作战纪律：五次部署法则（5 客户前不写死 Playbook）、负荷管理（1-2 大客户上限）
- 3.5 Gate 纪律：每阶段进入条件、交付物与检查清单

**第 4 章 工作坊：Echo-Delta 角色定位游戏（30 min · 小组）**

- 4.1 用角色卡理解作战单元：Delta（技术执行）/ Echo（业务策略）/ Engineering（基础设施）
- 4.2 现场情境卡分组判断角色主导，讨论分歧
- 4.3 讲师点评：分工解耦 × 战斗力整合

### 第二篇：Echo 业务策略（Day 1 下午）

**第 5 章 Echo 角色深度**

- 5.1 作战单元中的位置：Echo 是"政委与导航员"，Delta 是尖刀，Engineering 保阵地
- 5.2 官方定义（Echo 序列 / Deployment Strategist）："把客户的模糊直觉变成现实"；硬性要求 Python/R/SQL
- 5.3 ≠ 客户经理/售前：懂技术 / 定义问题 / 对落地负责 三条本质区别
- 5.4 汇报线隔离：定义问题但不背签单与定价指标
- 5.5 能力画像：业务理解、沟通、产品思维、学习敏捷度极强；技术深度中等

**第 6 章 Echo 的工作方法（Discovery 发现期）**

- 6.1 核心原则：第一周不写代码，听客户说话，成为内行人
- 6.2 干系人地图（SOP 1）：决策者 / 影响者 / 使用者 / 阻碍者 / 冠军用户；头三天找到冠军用户
- 6.3 业务流程诊断与痛点识别：结构化访谈 + 跟班观察；痛点分类矩阵（流程/数据/决策/协作）
- 6.4 数据资产盘点（SOP 2）："业务牵引"逆向盘点；常见陷阱
- 6.5 快赢场景筛选（SOP 3）：影响力 × 可行性二维打分；选"领导最关心、群众获得感最强"
- 6.6 Discovery Gate 检查清单：决策者/冠军用户/数据验证/决策层认可/黑话复述
- 6.7 场景拆解与技术选型：LLM 四层级金字塔（提示词→RAG→微调→Agent）；"从最简单开始"；选型三问
- 6.8 能力回注起点：Echo 负责"识别、抽象"，飞轮第一推动力

**第 7 章 工作坊：西岭需求调研 · 头脑风暴版（90 min · 小组，不用 AI）**

- 7.1 核心原则：Echo 靠想、Delta 靠做；训练判断力而非产出力
- 7.2 三个思维脚手架：四类失败模式（挖风险）/ 四层决策链（理干系人）/ 能力金字塔（选型）
- 7.3 演练流程：破冰分工 → 独立判断 → 脑暴一挖风险（风险墙）→ 脑暴二理干系人（权力×兴趣图）→ 脑暴三拆场景+选型 → 150 字全业务语言汇报
- 7.4 产出物：风险墙 + 干系人图 + 解决方案框架（三场景 + 选型 + 优先级 + 风险应对 + 数据不出域）+ 汇报话术

### 第三篇：Delta 技术执行（Day 2 上午）

**第 8 章 Delta 与 Vibe Coding**

- 8.1 Delta 角色定义：全栈特种兵（对标 Delta / FDSE），70/20/10 时间分配
- 8.2 AI 原生开发范式：从"手敲代码"转向"描述需求 + 审查判断"；opencode 实操
- 8.3 八环节工作流：Think → Plan → Build → Review → Test → Ship → Reflect
- 8.4 SPEC 驱动开发：先写规格再动手，Build 不重复技术参数
- 8.5 环境与依赖管理：Pyenv + Poetry、依赖锁、Streamlit 验证面板

**第 9 章 RAG 知识问答**

- 9.1 RAG 核心思想："开卷考试"；何时用 RAG / 微调 / 纯关键词
- 9.2 核心链路：读取 → 分块 → 向量化 → 检索 → 生成 → 来源引用
- 9.3 分块与参数：chunk_size / overlap / top-K / Embedding 选型
- 9.4 向量检索与混合检索：Chroma/Milvus、Dense+Sparse、Re-rank
- 9.5 四层排查法：文档层 → 分块层 → 检索层 → 生成层；数据漂移风险

**第 10 章 工作坊：政策法规 RAG 问答系统（90 min · 小组 + 代码智能体）**

- 10.1 场景：施工"政策问答"子场景，答案必须可追溯（政策文号/条款）
- 10.2 演练流程：需求诊断 → 生成 SPEC → 按 SPEC 实现（ingest/rag_query/streamlit）→ 建索引三问验证 → 代码审查 → 排查预埋 Bug → 版本发布
- 10.3 产出物：PRD + SPEC、RAG 代码、Streamlit 问答界面、三问验证记录、REFLECT

### 第四篇：Agent 与团队交付（Day 2 下午）

**第 11 章 Agent 系统设计**

- 11.1 Agent 的本质：决策循环——能根据中间结果自主决定下一步
- 11.2 适用边界：Agent vs 单次 LLM vs RAG；"从最简单开始"
- 11.3 六种 Agentic 设计模式：Prompt Chaining / Routing / 并行 / Orchestrator-Workers / Evaluator-Optimizer / 自主 Agent
- 11.4 Router 三路分流：low→quick / high→deep / uncertain→escalate；假阳性 vs 假阴性权衡
- 11.5 工具设计与安全：Guardrails、权限最小化、MCP、人机回环
- 11.6 自动化边界判断：FDE 方案设计的核心业务决策

**第 12 章 工作坊：工单智能分级路由 Agent（90 min · 小组 + 代码智能体）**

- 12.1 场景：施工"工单流转"子场景，三路分流（自动快过 / 深度审查 / 转人工）
- 12.2 演练流程：需求诊断 → 生成 SPEC（状态机）→ LangGraph 实现（analyze/quick/deep/escalate）→ 代码审查三确认 → 三路验证 → 版本发布
- 12.3 产出物：PRD + SPEC、Agent 代码、Streamlit 界面、三路验证记录、REFLECT

**第 13 章 工作坊：全团队交付与决策层汇报（45 min · 全团队）**

- 13.1 成果串联：方案框架 + 两个 Demo 整合为完整交付
