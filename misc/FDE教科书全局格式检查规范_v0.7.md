# FDE 教科书全局格式检查规范（v0.7）

> 用途：给协作者 / AI 代理做**全书格式扫描**的依据。扫描范围：`textbook/` 全部 17 个文件（00 导读 + 第 01–16 章），必要时含 `labs/`。
> 使用方法：按「A–F」六类逐项检查；每条给出**规则 → 反例 → grep 检查法**。扫完按文末《检查报告模板》逐文件记录问题。
> 配套：格式与写作的完整约定见 `AGENTS.md`（第 3–8 节）；本文档只列**扫描项**，是 AGENTS.md 的可执行检查清单。

---

## A. 编号与引用类（严重度 🔴）

### A1. 章节编号连续、无跳级
- **规则**：`#` 章 → `##` 节 → `###` 子节，禁止跳级（如 `##` 下直接 `####`）；节号（`N.x`）与子节号（`N.x.y`）连续无重复。
- **反例**：`## 15.2` 之后出现 `### 15.4`；`### 13.3.5` 夹在 `13.4.7` 之后。
- **grep**：`^#{2,3} ` 列出全部标题 → 人工核对连续性；检查每个 `### N.x.y` 的父节 `## N.x` 是否存在。

### A2. 无旧编号残留（历史重排后）
- **规则**：第 13 章旧编号 `13.6–13.11`、第 15 章旧编号 `15.5–15.9`、第 7 章旧速查号 `13.10` 等一律不得出现在正文（仅允许出现在导读「修订记录」的历史条目中）。
- **反例**：正文出现 `（15.6 的指标）`、`见 13.10 速查`。
- **grep**：`13\.(6|7|8|9|10|11)(\.\d)?` 与 `15\.(5|6|7|8|9)(\.\d)?` → 命中只允许在 `00_导读与体例说明.md` 的修订记录。

### A3. 交叉引用有效
- **规则**：一切 `N.x` / `N.x.y` 引用必须指向存在的小节；跨章引用用"第 N 章 N.x"或"（N.x）"，不写模糊的"前文/后文"。
- **反例**：引用 `14.8 撤出` 但 14.8 已改号；引用 `15.2.2 价值口径` 而该节已拆成 `15.2.2 / 15.2.3`。
- **grep**：`\d+\.\d+(\.\d+)?` 全库提取编号 → 与标题清单逐一比对；重排后必须全库 grep 同步。

### A4. 图号连续、图题齐全
- **规则**：每章 `*图 N-x：标题*` 按出现顺序连续（15-1 → 15-2 → 15-3…）；每张 mermaid 图下方必须有图题，图题数 = mermaid 数。
- **反例**：图题写成"图 15-2"但实际是第 3 张；mermaid 后无图题。
- **grep**：`^```mermaid` 计数 vs `^\*图 \d+-\d+` 计数，两数必须相等；图号去重后必须连续。

### A5. 表格表头分隔行
- **规则**：所有 markdown 表格必须有表头分隔行（`|---|`）。
- **反例**：只有表头行没有 `---` 分隔行。
- **grep**：扫描含 `|` 的多行块，检查是否成表（表头后紧跟 `|---`）。

## B. 格式类（严重度 🟡）

### B1. 无带圈数字（历史整改已清零，禁止回潮）
- **规则**：正文不得使用 `①②③…⑩`、`⑴⑵⑶`、`❶❷`；序号用 `1. 2. 3.` 或 `一、二、三`。这是全书最常被检查的项。
- **反例**：`三类公式：①效率型 ②质量型 ③收入型`。
- **grep**：`[①②③④⑤⑥⑦⑧⑨⑩⑪⑫⑬⑭⑮⑴⑵⑶⑷⑸⑹⑺⑻⑼⑽❶❷❸❹❺]`

### B2. 标题尽量不用括号（2026-08 新规）
- **规则**：章节标题（`#`/`##`/`###`）不得用括号装载说明性内容；**保留类例外**——术语注释（`Airbus（空中客车）`、`（Embedding）`、`（HITL）`）、时间范围（`第一阶段（2018–2022）`）、环节时长（`（约 10 分钟）`）、DoD 术语。
- **反例**：`## 8.1 知识背景（呼应第 7 章）`、`### 15.3 估算方法与汇报话术（给区间不给单点）`、`## 13.3 微调（进阶选读）`。
- **grep**：`^#{2,3} .*[（(]` → 命中逐条判断是否"保留类"；说明性括号应删或并入正文（用冒号/破折号）。

### B3. 无目录式概述引文（2026-08 新规）
- **规则**：大节/小节标题下的引言不得是"本节讲 X、Y、Z（带编号罗列）"的目录式概述；开篇词应为正文式（讲清"这块解决什么问题、为什么重要"），可配流程图但不罗列编号。
- **反例**：`> 三节讲透这块：门槛·动机·信任（15.3.1）…试点→推广 Gate（15.3.3）`、`> 本节用两条回答：价值证据链（15.2.1）…五口径（15.2.2）`。
- **grep**：`> (本节|三节|下面|用两条回答|用三个话题).*（\d+\.\d+`（罗列编号的概述引文）。

### B4. 全角/半角标点
- **规则**：简体中文正文用全角标点（，。；：""''（））；半角标点只用于英文/数字/代码场景。
- **反例**：中文句子里出现 `,` `.` `:` `(` `)`；英文单词后应留空格（`FDE 方法` 而非 `FDE方法`）。
- **grep**：中文相邻半角标点 `[\u4e00-\u9fff][,.;:()]`（正则扫描）。

### B5. 引用块语义正确（GitHub Alert）
- **规则**：语义化引用块必须独占行：`> [!NOTE]` / `> [!TIP]` / `> [!IMPORTANT]` / `> [!CAUTION]`；Alert 标记后接正文；普通引用不要滥用 Alert。
- **反例**：`> [!NOTE]` 后无内容；把 IMPORTANT 当普通段落用。
- **grep**：`^> \[!` → 检查是否独占行且语义匹配（警告用 CAUTION、关键结论用 IMPORTANT、提示用 TIP、说明用 NOTE）。

### B6. mermaid 布局规则
- **规则**：元素（节点）> 4 个一律垂直布局（`flowchart TB`/`TD`）；≤ 4 个才允许水平（`flowchart LR`）；循环图即使元素多也按垂直成环。
- **反例**：6 个节点用 `flowchart LR`。
- **grep**：`^flowchart (LR|RL)` → 数该图节点数，>4 则违规。

### B7. 代码块标注语言
- **规则**：代码/伪代码块标注语言（` ```text`、` ```python`、` ```mermaid` 等），不裸写 ` ``` `。
- **grep**：``` ` ``` ``` 开头的代码块是否都有语言标注（扫描 ``` 行）。

## C. 内容纪律类（严重度 🔴）

### C1. 无内部解释性表述
- **规则**：不出现"我们改过/换过方案""从 X 讲起而不是 Y""这是 1.1 想纠正的误区"等内部口吻（AGENTS.md 5.1）。读者拿到的是最终版，不知内部演变。
- **反例**：`（原第 7 章 7.3/7.4/7.8.1 的模型内容并入本章）`、`已并入本章 13.1/13.2`、`这是合并后的写法`。
- **grep**：`原第|并入本章|移入本章|从.{0,6}讲起|想纠正|改为|换成|以前是|历史版本`

### C2. 无旧口径残留（跨轮次同步）
- **规则**：早期口径不得残留——`两条算力路线（B300/昇腾）`（已改"合规可得性分层"）、`选型三要素`（已改"选型三问"）、`决策三要素`、`双栈`、`推理 vs 微调硬件差异（13.1–13.2）`（已移 13.3.3）等。
- **反例**：Ch7/Ch8/Ch9 引用 `选型三要素（13.2）`；`两条算力路线 B300 / 910C`。
- **grep**：`决策三要素|选型三要素|两条算力路线|双栈|B300 / 910C|B300 还是昇腾|B300 或昇腾`

### C3. 官方引文可点击 + "教材提炼"标注
- **规则**：官方/事实性引文必须有可点击 URL（或注明出处）；教材自创概念/结论必须标"教材提炼"，不冒充厂商官方术语。
- **反例**：`根据 NVIDIA 官方数据` 无链接；`量化公式` 未标"教材提炼"。
- **grep**：无链接的 `（官方|据.*官方|来源：.*）` 表述；正文出现厂商术语未标"教材提炼"。

### C4. 时效标注
- **规则**：动态数据（价格/型号/行业事件）标注"信息截至 YYYY 年 MM 月"；落地前以官方资料复核。
- **反例**：报 2026 年 GPU 价格却不写"信息截至"。
- **grep**：含 `≈|价格|报价|万元|元/` 的量化句是否带时效标注。

### C5. 术语统一
- **规则**：按 AGENTS.md 术语表统一（FDE 三层含义、三角色、四条红线、四阶段、能力回注、本体建模口径等）；"客户"可理解为外部客户或内部被服务部门。
- **反例**：`Echo 负责判断、Delta 负责实现` 与 `Echo 主责判断、Delta 主责施工` 混用；`本体论` 与 `Ontology` 不统一。
- **grep**：关键术语双写抽查（`Echo.*判断|Delta.*施工` 等）。

### C6. 无重复/雷同段落
- **规则**：同一信息不要在相邻小节重复展开（如开篇词与首子节重复"门槛动机信任"）；跨节引用而非复制。
- **反例**：15.3 开篇与 15.3.1 开头重复整句。
- **grep**：人工通读相邻小节首段，比对长句重复；或对全库做相似度抽查。

## D. 体例类（严重度 🟡）

### D1. 每章统一体例
- **规则**：章节模板齐全——章首属性块（定位/产出/建议读者/前置）→ 本章导学（学习目标/前置知识/章节地图）→ 正文 → 反模式与红线 → 本章小结（+ 动手自检）→ 练习与思考（基础/进阶/挑战）→ 延伸阅读（FDE-101 链接统一格式）。
- **grep**：每章是否都有 `## 反模式与红线`、`## 本章小结`、`## 练习与思考`、`## 延伸阅读` 四件套。

### D2. 大节开篇词
- **规则**：每个 `##` 大节应有正文式开篇词（讲"这块解决什么问题、为什么重要"）；禁止空标题直入子节、禁止目录式罗列（B3）。
- **grep**：`^## \d+\.\d+` 标题后第一行是否正文段（非 `>`、非 `###`）。

### D3. 实操章体例
- **规则**：实操章含 任务书 → 演练流程 → 产出物清单 → 验收标准（DoD）→ 适配说明；实操章文件引用 labs 用"见《实验手册》`labs/<文件名>`"。
- **grep**：实操章（6/8/10/12/16）是否含 `## 16.x 任务书|产出物|DoD` 结构。

## E. 全库一键扫描命令（PowerShell 批量）

```powershell
# 在 textbook/ 下运行；命中即可疑，逐条人工判断
# 1. 带圈数字
rg "[①②③④⑤⑥⑦⑧⑨⑩⑪⑫⑬⑭⑮⑴⑵⑶⑷⑸⑹⑺⑻⑼⑽❶❷❸❹❺]"
# 2. 标题括号（说明性）
rg "^#{2,3} .*[（(]"
# 3. 目录式概述引文
rg "^> (本节|三节|下面|用两条回答|用三个话题).*\d+\.\d+"
# 4. 旧编号残留
rg "13\.(6|7|8|9|10|11)(\.\d)?|15\.(5|6|7|8|9)(\.\d)?"
# 5. 旧口径残留
rg "决策三要素|选型三要素|两条算力路线|双栈|B300 / 910C|B300 还是昇腾|B300 或昇腾"
# 6. 内部解释性表述
rg "原第|并入本章|移入本章|已并入|想纠正|改口径|换方案"
# 7. 图题数 vs mermaid 数（每章计数比对）
# 8. mermaid 水平布局
rg "^flowchart (LR|RL)"
# 9. 标题跳级
rg "^#### "          # #### 只在极特殊情况出现，检查是否跳级
# 10. 英文与中文间缺空格（抽查）
rg "[一-龥][A-Za-z]|[A-Za-z][一-龥]"
```

## 严重度约定

- 🔴 = 事实/引用/编号/纪律（必须修，影响可读可溯可教）
- 🟡 = 格式/体例/表述（建议修，统一全书观感）
- 扫描只负责**发现**；修复按 AGENTS.md 9.2 分批执行，每批后更新 `00_导读与体例说明.md` 修订记录。
