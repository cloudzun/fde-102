# 人工智能工程师（高级）FDE 认证培训 · 教科书编写大纲（实战训练版）

> **教科书定位：** 面向 FDE（Forward Deployed Engineer，前沿部署工程师）能力培养的**实战训练教材**。
> **与《AI 时代的 FDE》（FDECore）的层次区分：** FDECore 是**方法论教材**——讲清"为什么、体系是什么"（规范、经济学、SOP 全集）；本书是**实战训练教材**——讲清"怎么练、怎么交付"（角色分工、实验闭环、成果验收）。FDECore 的规范术语本书直接沿用，但**每章只做到"够用即止"，把空间留给动手；深层逻辑与全量 SOP 以"延伸阅读 → FDECore 第 X 章"标注**，不重复展开。
> **贯穿主线：** Echo（靠想·判断力）→ Delta（靠做·施工力）双角色分工，用**西岭市民服务平台**单案例贯穿全书——前一章产出的"施工图"，就是后一章施工的"任务书"。
> **编写原则：** 每章都是**结构独立、可自由拼接**的模块，不依赖固定课时。内容做扎实，交付时依客户天数/基础删减章节即可。

## 一、全书绪论与使用指南

**写作要点（放在正文最前）：**
- 一句话交代 FDE 是什么、本书能让你练出什么。
- 一张"本书与 FDECore 的关系表"——明确读者何时该翻哪本书：
  | 你想清楚的问题 | 读哪本 | 到哪 |
  |---|---|---|
  | FDE 为什么在 AI 时代值钱（经济学/财务） | FDECore | 第 2 章、第 13 章 |
  | FDE 的完整 SOP 全集 | FDECore | 第 5–9 章 |
  | 我要怎么把需求做出来、把 Demo 跑通 | 本书 | 全部实操章 |
  | 政务/企业私有化落地的红线清单 | 两边交叉读 | 本书 Ch7/13 + FDECore Ch14/16 |
- **四个贯穿全书的"教学道具/红线"**（在绪论讲清，后续每章复用，贯穿于案例红线）：
  1. 数据不出域（政务红线，决定私有化选型）
  2. 答案可追溯（RAG/政务 AI 准入门槛）
  3. 敏感件零漏判（Agent 验收硬指标）
  4. 人能判断、AI 能执行（Echo/Delta 分工哲学，不是 AI 越强人越省事）
- **每章统一体例**（见"二、章节写作模板"）。

## 四、各章编写要点

### 第 1 章  FDE 是什么
- **类型：** 知识单元 · 认知打底
- **本节定位：** 只到"能分清角色、能对同事讲清"，不做学术深挖。
- **节结构：**
  - 1.1 定义与一句话箴言："FDE is the glue between our products and our customers"
  - 1.2 三层含义：岗位 / 团队 / 方法论（类比 DevOps）
  - 1.3 三重角色融合：全栈工程师 × 业务顾问 × 产品经理
  - 1.4 ≠ 外包 ≠ 咨询：核心分野"从卖人力到卖能力"，判断标准=公司能力是否增长
  - 1.5 AI 时代 FDE 复兴：五大鸿沟一览（模型≠产品 / 数据合规 / 微调工程 / 系统集成 / 搁板软件）
- **反模式：** 把 FDE 当"驻场程序员 / 能写代码的售前"。
- **延伸阅读：** FDECore 第 1 章、第 15 章（AI 重塑 FDE）。

### 第 2 章  为什么需要 FDE
- **类型：** 知识单元 · 认知打底（点到为止）
- **本节定位：** 只求学员"信"，不求推导全。财务与经济细节放延伸。
- **节结构：**
  - 2.1 死亡螺旋：传统项目制"局部理性、全局自杀"
  - 2.2 四种交付模式：SaaS / 咨询 / 外包 / FDE+平台
  - 2.3 能力回注飞轮 + 经验曲线（Cₙ=C₁×n⁻ᵅ）核心直觉
  - 2.4 Palantir 财务铁证（毛利率 50%→82.4%、NRR 118%）——用一两张图讲"越做越省"
  - 2.5 FDE 退化警示：自检"平台是否在增长"
- **反模式：** 只见人天计费、忽视能力沉淀。
- **延伸阅读：** FDECore 第 2 章、第 13 章（财务证据）、第 3 章（平台体系）。

### 第 3 章  FDE 交付四阶段与能力回注
- **类型：** 知识单元 · 全流程地图
- **本节定位：** 给全书搭建"地图"，实操章都挂在四阶段上。
- **节结构：**
  - 3.1 四阶段漏斗：Discovery → Prototype → Build → Scale
  - 3.2 能力回注四步法：识别 → 抽象 → 集成 → 验证
  - 3.3 迭代哲学：碎石路 → 铺装公路；五次部署法则
  - 3.4 Gate 纪律：每阶段进入条件 / 交付物 / 检查清单
- **反模式：** 过早标准化 / 订制度时跳过 Gate。
- **延伸阅读：** FDECore 第 5–9 章（四阶段各章 SOP）。

### 第 4 章  Echo 与 Delta 双角色 + 角色定位游戏（实操）
- **类型：** 实操单元 · 角色确立
- **本节定位：** 靠"玩"让学员认领角色，确立全书分工哲学。
- **节结构：**
  - 4.1 作战单元：Echo（政委/导航员）、Delta（尖刀）、Engineering（保阵地）
  - 4.2 Echo / Delta 职责、能力画像对照
  - 4.3 分工哲学："人能判断、AI 能执行"
  - 4.4 角色定位游戏：角色卡 + 情境卡分组判断、讨论分歧、讲师点评
- **可复用的交互素材（自包含 HTML，直接嵌入/发布）：** `实操一-Echo-Delta角色定位游戏.html`。
- **产出物：** 每个人明确"我在毕业项目里扮演谁、职责边界、能力短板"。
- **延伸阅读：** FDECore 第 10 章（角色体系）、第 11 章（四阶段中的角色协作）。

### 第 5 章  Echo 工作法 · Discovery
- **类型：** 知识单元 · Echo 侧方法
- **本节定位：** 只做"够用"的 SOP 提炼，实操一马上要用。
- **节结构：**
  - 5.1 核心原则：第一周不写代码、成为内行人
  - 5.2 三个思维脚手架（本书贯穿使用，实操一的骨架）：
    - 四类失败模式（数据不可用 / 业务不配合 / 合规卡住 / ROI 说不清）
    - 四层决策链（决策层 / 操作层 / 技术层 / 监管层）
    - LLM 四层能力金字塔（提示词→RAG→微调→Agent，"从最简单开始"）
  - 5.3 Discovery SOP 提炼：干系人地图（SOP1）/ 痛点诊断 / 数据资产盘点（SOP2）/ 快赢筛选（SOP3）
  - 5.4 场景拆解与技术选型三问
- **反模式：** 一上来就套模板 / 用 AI 堆产出代替判断。
- **延伸阅读：** FDECore 第 5 章（Discovery 全量 SOP）、第 16 章 16.2.1（AI 辅助 Discovery）。

### 第 6 章  实操一 · 西岭需求调研 →《解决方案框架》
- **类型：** 实操单元 · **角色=Echo** · **模式=头脑风暴（全程禁用 AI）**
- **承接：** 读第 5 章脚手架；用第 4 章角色定位完成组内分工。
- **任务书：** 客户方（西岭市民服务平台）"原始需求"——模糊、藏风险，材料即彼第 0 章的客户需求。
- **演练流程：** 破冰分工 → 个人独立判断 → 脑暴一挖风险（风险墙）→ 脑暴二理干系人（权力×兴趣图）→ 脑暴三拆场景+选型 → 150 字业务语言汇报。
- **产出物：** 风险墙 + 干系人图 + **《解决方案框架》**（三场景 + 选型 + 优先级 + 风险应对 + 数据不出域）+ 汇报话术。
- **验收标准：** 各组 150 字业务语言答辩通过；《解决方案框架》即为后续实操的任务书。
- **可复用素材：** 客户需求材料（第 0 章）、解决方案框架模板（附录 A）、`实操一` 头脑风暴脚本。
- **延伸阅读：** FDECore 第 5 章。

### 第 7 章  Delta 工作法 · Vibe Coding 与工程纪律
- **类型：** 知识单元 · Delta 侧方法（重"手势/命令"）
- **本节定位：** 教"怎么让 AI 替你执行 + 人在 checkpoint 把关"，三个施工实操的公共底座。
- **节结构：**
  - 7.1 Delta 角色：全栈特种兵（对标 Delta/FDSE），70/20/10 时间分配
  - 7.2 AI 原生开发范式：描述需求 + 审查判断；opencode 实操
  - 7.3 gstack 八环节工作流：office-hours → spec → autoplan → build → review → qa → ship → retro
  - 7.4 SPEC 驱动开发：先写规格再动手（注意第 4 环节正式名为 build）
  - 7.5 防 Agent 翻车的工程纪律：测试数据外部给定、启动提示词信息块、驱动指令执行纪律（见后）
- **反模式：** 让 Agent"全自动"一把梭、不设 checkpoint；Agent 自己出题自己考。
- **延伸阅读：** FDECore 第 16 章 16.2（AI 辅助四阶段）。

### 第 8 章  实操二 · 诉求智能分类器（场景 A）
- **类型：** 实操单元 · **角色=Delta** · **模式=AI 施工**（opencode+gstack）
- **承接：** 第 6 章《解决方案框架》中的场景 A。
- **任务书：** 市民诉求智能分类（一次 LLM 调用零样本分类）——教学点："怎么让 AI 替你跑流程"。
- **演练流程：** 需求诊断 → 启动提示词向导拼装（7 项信息块）→ SPEC → 按 SPEC 实现（调用 LLM 分类 + CSV 落盘 + Streamlit 验证面板）→ 代码审查 → 用外部给定 25 条测试集验证 → 版本发布 → retro。
- **产出物：** PRD + SPEC、分类器代码、Streamlit 界面、测试验证记录、retro.md。
- **验收标准：** 测试集不得自行改动/重新生成，分类准确率达约定阈值。
- **可复用素材：** `实操二-启动提示词向导.html`、测试集 CSV、gstack 流水线。

### 第 9 章  RAG 知识问答：答案可追溯
- **类型：** 知识单元 · 技术方法（对准实操三）
- **节结构：**
  - 9.1 RAG 核心思想："开卷考试"；何时用 RAG / 微调 / 纯关键词
  - 9.2 核心链路：读取 → 分块 → 向量化 → 检索 → 生成 → 来源引用
  - 9.3 分块与参数：chunk_size / overlap / top-K / Embedding 选型
  - 9.4 向量检索与混合检索：Dense+Sparse / Re-rank
  - 9.5 四层排查法：文档层 → 分块层 → 检索层 → 生成层；数据漂移
- **反模式（政务重点）：** 答案给不出文号/条款（违反"答案可追溯"红线）。
- **延伸阅读：** FDECore 第 16 章 16.4（本土技术栈选型）、16.2.4（能力回注）。

### 第 10 章  实操三 · 政策法规 RAG 问答系统（场景 B）
- **类型：** 实操单元 · **角色=Delta** · **模式=AI 施工**
- **承接：** 第 6 章《解决方案框架》中场景 B。
- **任务书：** 政策问答（政策库西岭政策库）——**答案必须可追溯（政策文号/条款）**。
- **演练流程：** 需求诊断 → 生成 SPEC → 按 SPEC 实现（ingest / rag_query / streamlit）→ 建索引三问验证 → 代码审查 → 排查预埋 Bug → 版本发布 → retro。逐轮复用实操二留下的 AGENTS.md / retro.md。
- **产出物：** PRD + SPEC、RAG 代码、Streamlit 问答界面、三问验证记录、retro.md。
- **验收标准：** 每条答案带来源；通过"建索引三问"与"答案可追溯"校验。
- **可复用素材：** `实操三-启动提示词向导.html`、政策语料（md/pdf/docx 混合，含格式杂乱考验分块）。

### 第 11 章  Agent 系统设计：自动化边界
- **类型：** 知识单元 · 技术方法（对准实操四）
- **节结构：**
  - 11.1 Agent 本质：决策循环（根据中间结果自主决定下一步）
  - 11.2 适用边界：Agent vs 单次 LLM vs RAG；"从最简单开始"
  - 11.3 六种 Agentic 设计模式：Prompt Chaining / Routing / 并行 / Orchestrator-Workers / Evaluator-Optimizer / 自主 Agent
  - 11.4 Router 三路分流：low→quick / high→deep / uncertain→escalate；假阳性 vs 假阴性权衡
  - 11.5 工具设计与安全：Guardrails、权限最小化、MCP、人机回环
  - 11.6 自动化边界判断：FDE 方案设计的核心业务决策
- **反模式（政务重点）：** 敏感件漏判（违反"阳性件零漏判"红线）、AI 直接拍板进生产关键链路。
- **延伸阅读：** FDECore 第 16 章（人机协同红线 / Agent 化）。

### 第 12 章  实操四 · 工单智能分级路由 Agent（场景 C）
- **类型：** 实操单元 · **角色=Delta** · **模式=AI 施工**
- **承接：** 第 6 章《解决方案框架》中场景 C。
- **任务书：** 工单流转三路分流（自动快过 / 深度审查 / 转人工）——验收硬指标**敏感件零漏判**。
- **演练流程：** 需求诊断 → 生成 SPEC（状态机）→ LangGraph 实现（analyze / quick / deep / escalate）→ 代码审查三确认 → 三路验证 → 版本发布 → retro。复用前两实操的 AGENTS.md / retro.md。
- **产出物：** PRD + SPEC、Agent 代码、Streamlit 界面、三路验证记录、retro.md。
- **验收标准：** 三路分流 + 人工回环跑通；敏感件零漏判；自动化边界说明。
- **可复用素材：** `实操四-启动提示词向导.html`、状态机 SPEC 模板。

### 第 13 章  实操五 · 全团队交付与决策层汇报
- **类型：** 实操单元 · **角色=全团队** · **模式=头脑风暴 + 汇报**
- **本节定位：** 把 Echo 的框架 + Delta 的三个 Demo 整合成完整交付，学会对决策层讲价值。
- **节结构：**
  - 13.1 成果串联：方案框架 + 三个 Demo 整合
  - 13.2 ROI 量化：五步法（假设 → 效率 → 质量 → 敏感度 → 锁定）
  - 13.3 合规与部署收口：数据不出域、私有化方案；能力回注思考（碎石路→铺装公路）

## 五、贯穿案例与角色任务书的设计

> 全书唯一案例是**西岭市民服务平台**。所有知识都要落到这个案例上，所有实操共用同一份《解决方案框架》。

**西岭案例的"四个藏雷点"（贯穿第 6–13 章的教学交通）：**
1. **数据不可用**——政策库 PDF/Word/扫描件格式杂乱、数据未必拿得齐
2. **业务不配合**——坐席担心 AI 抢饭碗（"你们 AI 上来是不是就不需要我们了"）
3. **合规卡住**——数据不出政务外网是红线；市数据局"一票叫停"
4. **ROI 说不清**——错分率没人统计过，价值难量化

**角色任务书贯穿线：**
- 第 6 章 Echo 产出《解决方案框架》→ 拆出场景 A/B/C → 作为第 8/10/12 章的任务书。
- 第 8/10/12 章 Delta 施工时，**逐轮复用上一实操的 AGENTS.md / retro.md**，体现项目连续性。
- 第 13 章把"A/B/C 三个 Demo"+框架整合为一个完整交付物。

## 七、防 Agent 翻车的三条工程纪律（多实操通用写作点）

> 第 7 章立原则，第 8/10/12 章逐章落实，保证实操在真实 Agent 运行时稳定出结果。

1. **测试数据必须外部给定**——写进启动提示词，Agent 落盘成 CSV，"不得自行改动或重新生成"，防止 Agent 自己出题自己考。
2. **启动提示词 7 项信息块**——背景 / 要做什么 / 输入输出 / 技术选型（含理由）/ 数据现状 / 测试集 / 验收口径 / 约束，每项写死不让 Agent 猜。
3. **驱动指令执行纪律**——严格按 gstack 8 环节逐步执行、禁止全自动（每环节完成必须停下汇报、获准才流转）、关键决策列选项等拍板、环节产出落盘、从 office-hours 开始。
