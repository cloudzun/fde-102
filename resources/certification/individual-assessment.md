# 个人评价与交叉检查（individual-assessment）

> **目的：** 防止"团队产出 = 个人能力"的误判；防止角色固化。
> **规则：** ① 每个学员按自己认领的主角色评个人项；② **每人还须完成一项对方角色的基础能力检查**（Echo 学员做一项 Delta 基础能力、Delta 学员做一项 Echo 基础能力），合格即可，不要求达到主角色水平。

## 一、Echo 个人评价项

| 评价项 | 证据 | 通过判据 |
|--------|------|---------|
| 个人成功标准 | 个人提交的场景验收口径（八字段中至少 3 字段为个人执笔） | 口径有业务依据、标注来源或教学初始值 |
| 用户反馈判断 | 个人记录的用户（小王/陈主任）反馈与判断 | 能区分"反馈"与"真需求"，有取舍 |
| 价值证据 | 个人完成的价值证据链片段（15.2） | 五口径不混用、参数可复算 |
| 采用障碍诊断 | 个人对"门槛·动机·信任"的某一诊断（15.4） | 诊断指向具体人/动作 |
| 业务回注判断 | 个人提出的本体候选（15.7） | 区分"西岭内容"与"通用机制" |

## 二、Delta 个人评价项

| 评价项 | 证据 | 通过判据 |
|--------|------|---------|
| 个人故障排查 | 个人解决的某个环境/运行故障记录（troubleshooting 口径） | 现象→原因→修复→验证完整 |
| 测试与证据 | 个人写的测试用例或验收数据 | 测试集有来源、结论有限定语 |
| 生产差距判断 | 个人对某 MVP 的八项 Gate 差距判断（14.5） | 差距具体、有对应动作 |
| 回滚 | 个人完成的一次回滚演练记录 | 回滚路径可用（切回旧版本） |
| 工程回注判断 | 个人提出的工具/模块复用候选 | 有输入—输出契约描述 |

## 三、对方角色基础能力检查（防角色固化）

| 主角色 | 需完成的一项对方角色检查 | 最低要求 |
|--------|--------------------------|---------|
| Echo 学员 | Delta 基础：跑通一次最小 API 调用并写测试断言 | 能独立完成最小启动（environment-check 1.6） |
| Delta 学员 | Echo 基础：把某场景的验收口径讲给外行听（≤150 字） | 无技术黑话、口径可追溯 |

> 该项只判"合格/不合格"，不合格给一次补做机会，不纳入等级评分。
